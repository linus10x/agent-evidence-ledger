**Goal:** Build a standalone, append-only, tamper-evident ledger of agent decisions — binding each decision's payload, ordinal sequence, and authority tier into a hash chain — whose `verify()` returns a structured verdict NAMING which of five forgery classes (edit, delete, reorder, bypass, truncation) was detected and at which index, and which carries sovereign-veto and auto-demote-on-drift as ordered record types. Maps to SEC Rule 17a-4(f)(2)(i)(A) (the audit-trail alternative). Record-integrity ONLY; no PKI, no storage backend, no drift detector. (Task 5, v15 — the "ONE runnable primitive a frontier-lab verifiability engineer can drop in" build.)

**Architecture:** Pure-Python, zero-dependency. A `Ledger` accumulates frozen entry/veto/demote records; each record's hash binds `canonical(record) || prev_hash`. `verify(ledger, expected_head=..., executed_action_ids=...)` walks genesis to head and runs five isolated detection checks, returning a frozen `LedgerVerdict`. The demo defeats a naive verifier on each forgery class, then shows the governed verify catching it; the test suite is the control and each detection check has a documented one-line strip-point whose removal turns exactly one test RED.

**Tech Stack:** Python 3.11+ standard library only (`hashlib`, `json`, `dataclasses`, `enum`). pytest if present, pure-`unittest` fallback otherwise. No network, no pip install, no make.

## 2. Exact interfaces (signatures + field lists; NO bodies)

### 2.1 `records.py`

```
GENESIS_PREV_HASH: str = "0" * 64        # the fixed predecessor hash for seq 0 (sha256 hex width)

class RecordKind(enum.Enum):
    DECISION = "decision"
    VETO     = "veto"
    DEMOTE   = "demote"

@dataclass(frozen=True)
class DecisionEntry:
    seq: int                 # ordinal, gap-free, strictly +1 from genesis; bound INTO the hash (defeats reorder)
    authority_tier: int      # integer tier the agent held at decision time (higher int = more authority); bound INTO the hash
    action_id: str           # the id of the governed action this entry records a receipt for (defeats bypass)
    payload: str             # the decision content; treated as opaque DATA, never instructions
    prev_hash: str           # stored hash of the predecessor record
    hash: str                # stored hash of THIS record == entry_hash(canonical(self_without_hash), prev_hash)
    kind: RecordKind = RecordKind.DECISION

@dataclass(frozen=True)
class VetoRecord:
    seq: int                 # ordinal position in the SAME chain (its value is its ORDER relative to decisions)
    authority_tier: int      # the tier of the higher authority issuing the veto
    vetoes_action_id: str    # the action_id this veto blocks/overrides
    reason: str              # opaque DATA
    prev_hash: str
    hash: str
    kind: RecordKind = RecordKind.VETO

@dataclass(frozen=True)
class DemoteRecord:
    seq: int                 # ordinal position; proves WHEN the demotion took effect relative to decisions
    from_tier: int           # authority tier before demotion
    to_tier: int             # the lower authority tier after demotion (to_tier < from_tier)
    drift_signal_id: str     # id of the EXTERNALLY-supplied drift signal (the primitive does NOT detect drift)
    prev_hash: str
    hash: str
    kind: RecordKind = RecordKind.DEMOTE
```

Notes for implementer: each record's `hash` field is EXCLUDED from its own canonical serialization (you cannot hash a value that contains its own hash). `canonical()` serializes every field EXCEPT `hash`. The `kind` discriminator is INCLUDED in canonical bytes so a veto and a decision with otherwise-equal fields produce different hashes (prevents a record-type swap from passing).

### 2.2 `canonical.py` — the pinned deterministic encoding (lock with a test)

```
def canonical(record) -> bytes:
    """Deterministic, machine-independent serialization of a record's hashed fields.
    Pinned encoding (DO NOT change without re-pinning the known-digest test):
      1. Build an ordered dict of EVERY field except `hash`, with `kind` rendered as its .value string.
      2. json.dumps(d, sort_keys=True, separators=(',', ':'), ensure_ascii=True)
      3. .encode('utf-8')
    sort_keys makes field order irrelevant; separators removes whitespace; ensure_ascii makes the
    byte stream identical across locales/machines. This is the reproducibility contract."""

def entry_hash(record, prev_hash: str) -> str:
    """sha256( canonical(record) + b'|' + prev_hash.encode('utf-8') ).hexdigest()
    The b'|' domain-separator prevents a canonical-bytes/prev-hash boundary ambiguity."""
```

The hash is reproducible across runs and machines BECAUSE the encoding is fully pinned. This is locked by `test_known_entry_known_digest` (a fixed entry's hash equals a literal hex string committed in the test — if anyone changes the encoding, that test goes RED).

### 2.3 `ledger.py` — the append API

```
class Ledger:
    def __init__(self) -> None: ...                 # empty; head == GENESIS_PREV_HASH, count == 0
    def append_decision(self, *, authority_tier: int, action_id: str, payload: str) -> DecisionEntry: ...
    def append_veto(self, *, authority_tier: int, vetoes_action_id: str, reason: str) -> VetoRecord: ...
    def append_demote(self, *, from_tier: int, to_tier: int, drift_signal_id: str) -> DemoteRecord: ...
    @property
    def head(self) -> str:  ...                      # hash of the last record, or GENESIS_PREV_HASH if empty
    @property
    def count(self) -> int: ...                      # number of records (== next seq)
    @property
    def records(self) -> tuple: ...                  # immutable snapshot of all records in append order

    def head_anchor(self) -> tuple[str, int]: ...    # (head, count) checkpoint — the EXTERNAL ANCHOR for truncation/fork
```

`append_*` assigns `seq = self.count`, `prev_hash = self.head`, computes `hash = entry_hash(record, prev_hash)`, appends, returns the frozen record. Authority tier is bound into EVERY decision entry (so "after demotion at seq N, later decisions carry the lower tier" is provable from the chain alone).

**Open-question #3 decision:** the head anchor is a RETURN VALUE (`head_anchor()` -> `(head, count)`), NOT a record inside the chain. Rationale: an anchor stored as an interior record would itself be subject to truncation (drop the tail including the anchor). The anchor's whole job is to be held OUTSIDE the chain (the agent attests/publishes it at a checkpoint) and passed back into `verify(expected_head=...)`. A tiny attestation record would defeat its own purpose.

### 2.4 `verify.py` — the structured verdict

```
FORGERY_CLASSES = ("edit", "delete", "reorder", "bypass", "truncation")

@dataclass(frozen=True)
class LedgerVerdict:
    valid: bool                    # True ONLY if all five checks pass
    forgery_class: str | None      # one of FORGERY_CLASSES on tamper; None when valid; "invalid" sentinel for malformed input
    index: int | None              # seq/position where the forgery was detected; None when valid
    detail: str                    # human-readable, names the failing assertion
    reg_cite: str                  # REG_CITE constant, always populated (the auditable anchor)
    head: str                      # recomputed head over the records as walked
    count: int                     # recomputed record count

def verify(records,
           *,
           expected_head: tuple[str, int] | None = None,
           executed_action_ids: frozenset[str] | None = None) -> LedgerVerdict:
    """Walk genesis->head; run the five detection checks IN ORDER; return the first failure
    NAMED, else a valid verdict. NEVER raises: malformed/unknown input returns
    LedgerVerdict(valid=False, forgery_class='invalid', ...). expected_head supplied -> truncation/fork
    check runs; executed_action_ids supplied -> bypass coverage check runs."""

REG_CITE: str = (
    "SEC Rule 17a-4(f)(2)(i)(A) — 17 CFR 240.17a-4(f)(2)(i)(A) (audit-trail alternative): "
    "a complete time-stamped audit trail recording all modifications to and deletions of a record, "
    "enabling re-creation of the original; retention 6 yrs per 240.17a-4(a). "
    "2022 amendment SEC Release 34-96034."
)
```

**Open-question #2 decision (verdict shape, finalized):** fields are exactly `valid, forgery_class, index, detail, reg_cite, head, count`. `forgery_class` is one of the five named strings on a forgery, the literal `"invalid"` on malformed input (distinct from the five so a reviewer can tell "we caught a forgery" from "we refused garbage"), and `None` when valid. When `valid is False` AND `forgery_class` is one of the five, `index` is always the integer position of the detected forgery.

**Detection-check order inside `verify` (each is an isolated block — these are the strip-points):**

1. `_check_input_shape(records)` — fail-closed guard: records is a sequence; each is one of the three known dataclasses; required fields present and correctly typed (int seq/tiers, str hashes of len 64, bool excluded from int via `isinstance(x,bool)`). On failure -> `forgery_class='invalid'`. (Not one of the five; this is the malformed-input guard.)
2. `_check_links_and_edit(records)` — recompute `entry_hash(record_without_hash, record.prev_hash)` for each; if it != stored `record.hash` -> **edit** at that seq. (STRIP-POINT E.)
3. `_check_continuity(records)` — for each record assert `record.prev_hash == predecessor.hash` (genesis predecessor == `GENESIS_PREV_HASH`); a break -> **delete** at that seq. (Delete severs the stored-prev-hash linkage.)
4. `_check_sequence(records)` — assert `record.seq == index` for every position (gap-free, strict +1 from 0). Because `seq` is bound into the hash, swapping two records makes their recomputed hashes inconsistent with position -> **reorder** at the first out-of-order seq. (STRIP-POINT R.)
5. `_check_truncation(records, expected_head)` — if `expected_head` is supplied, recompute `(head, count)` and compare to the anchor; mismatch -> **truncation** at `index = count` (the position of the missing tail). (STRIP-POINT T — the centerpiece.)
6. `_check_coverage(records, executed_action_ids)` — if `executed_action_ids` is supplied, the set of `action_id` across DECISION entries (plus `vetoes_action_id` from vetoes that record a governed action) must EQUAL the executed set; any executed id not recorded -> **bypass** at the index of the first gap (or `count` if the unrecorded action has no position). Monotonic gap-free seq (from check 4) is a precondition.

Returns the FIRST failing check's named verdict. If all run-applicable checks pass -> `valid=True, forgery_class=None, index=None`.

**Why edit vs delete vs reorder are separable (so each strip-point fells exactly ONE test):**
- edit is caught by the *recompute-link* check (#2): the payload changed but the stored hash did not get recomputed by the attacker, so recompute != stored.
- delete is caught by the *continuity* check (#3): the attacker removed an interior record, so the successor's stored `prev_hash` points at a record no longer present — `prev_hash != predecessor.hash`. (An attacker who ALSO re-links would be re-writing hashes, which check #2 catches as edit; the delete test constructs the non-re-linked case so #3 is the firing check.)
- reorder is caught by the *sequence* check (#4): seq is bound into the hash and must equal position. A swap that did NOT recompute hashes also trips #2; the reorder test constructs the case where the attacker swapped positions but the seq-vs-position assertion is the firing check (i.e. the test asserts `forgery_class == 'reorder'`, which only holds if #4 fires before #2 would — see check-order note below).

**Check-order subtlety the implementer MUST honor:** the tests assert a SPECIFIC `forgery_class` per scenario, so each forgery fixture must be constructed to trip its OWN check as the first failure. The reorder fixture swaps two records' POSITIONS in the list WITHOUT altering their stored hashes/prev_hashes (so #2/#3 may also be inconsistent) — to make #4 the deterministic firing check, run `_check_sequence` BEFORE `_check_links_and_edit` is NOT acceptable (edit must stay early). Instead: the reorder fixture is built so that #2 and #3 still pass for the swapped records (achievable when the two swapped records are adjacent and the test rebuilds prev_hash/hash consistently for the swapped order but leaves seq values attached to the original records) and ONLY the seq-vs-position invariant breaks. The plan's canonical reorder fixture: take a valid 4-record chain, swap the list positions of records at index 1 and 2, and re-thread prev_hash+hash for the new order (so links/continuity hold) — the giveaway left behind is that record now at position 1 carries `seq == 2`. `_check_sequence` fires `reorder`. This keeps each forgery class mapped to exactly one strip-point. (Document this fixture-construction contract in `test_forgery_reorder.py`.)

**Open-question #4 decision (bypass interface):** `executed_action_ids: frozenset[str]` is passed to `verify()`. In the demo it is a small in-code fixture set of the action-ids that "really executed." This is a primitive, not an integration — no receipt store, no I/O. The coverage check cross-references that set against the recorded `action_id`s and names any acted-but-unrecorded id as **bypass**.

**Open-question #5 decision (authority vocabulary):** integer tiers, higher int = more authority (e.g. tier 2 -> tier 1 on demotion). Plain labels only in prose ("authority tier 2", "demoted to a lower authority tier"). No A0–A4, no ladder branding anywhere.

## 4. Failure modes + exit-code contract

### 4.1 Failure modes (all fail CLOSED — block/flag on error, never pass-on-error)
- **Crash mid-append.** Append is build-then-swap in memory: the new frozen record is computed fully, then appended; a partial record is never stored. A process killed mid-run leaves the ledger at its last fully-appended record; `verify` over that prefix is internally valid but, if an anchor exists, will be caught as truncation (correct: the dropped tail is absence). No silent acceptance.
- **Missing/empty records.** `verify([])` over an empty list with no anchor -> valid (vacuously, an empty ledger is a consistent empty ledger); with an `expected_head` whose count > 0 -> **truncation** (the whole tail is gone). An empty ledger that was anchored non-empty fails closed.
- **Malformed input.** Any non-sequence, unknown record type, wrong-typed field, or bad-width hash -> `forgery_class='invalid'` verdict, NEVER an exception. Tested by the fail-closed sweep. A control that raises can be swallowed by a caller and resolve to "proceed" — so it must not raise.
- **Mac asleep / scheduled context.** N/A by construction: nothing here is scheduled, networked, or long-running. The primitive is a synchronous in-process computation invoked by the demo or the test suite. No launchd job, no timer, no wake dependency.
- **Anchor absent.** If the caller does not supply `expected_head`, the truncation check is SKIPPED and the verdict cannot certify against absence — the demo and README state plainly that anchorless verify is the naive mode the truncation class defeats. This is a deliberate, documented surface, not a silent gap (proved by `test_naive_verify_accepts_truncated_chain`).

### 4.2 Exit-code contract (demo + test entrypoints)

`python3 -m agent_evidence_ledger.demo` (and `./demo.sh`):
- `0` — every scene ran AND its expected verdict held (valid chain verified valid; each of the 5 forgeries was caught with the correct class+index; veto/demote scenes verified). The demo SELF-CHECKS each scene's verdict and exits non-zero if any scene's actual verdict != expected.
- `2` — a scene's verdict did not match expectation (a control regressed — e.g. a forgery slipped). Fail closed: the demo prints the mismatch and exits 2, never 0.
- any other non-zero — unhandled error (the demo must never exit 0 on a crash).

`./run_tests.sh` (pytest if present, else `_testrunner`):
- `0` — all tests passed.
- non-zero — a test failed OR (only when pytest is absent AND the pure-python fallback also can't run) a clear note plus non-zero; never a misleading 0 on an unrun suite. The pure-python fallback (`_testrunner.py`) discovers and runs the `tests/` modules via `unittest` so a fresh clone with no pytest still gets a real pass/fail (audit-packet pattern).

## 5. One-command demo design (scene order)

`demo.py` injects `src/` on `sys.path` (zero-install), builds one valid ledger, then stages each defeat. Defeat-first: show the naive verifier ACCEPT, then the governed verify CATCH. Every scene self-checks and contributes to the exit code.

- **Scene 0 — VALID.** Build a 4-decision chain + a veto + a demote; `verify(expected_head=anchor, executed_action_ids=receipts)` -> `valid True`. Print head, count, reg_cite.
- **Scene 1 — EDIT.** Mutate entry seq 1's payload in place -> verify names `edit @ 1`.
- **Scene 2 — DELETE.** Drop the interior record at seq 2 -> verify names `delete @ 3` (successor).
- **Scene 3 — REORDER.** Swap positions 1 and 2 (links re-threaded, seq left attached) -> verify names `reorder @ 1`.
- **Scene 4 — BYPASS.** `executed_action_ids` contains an off-book id with no entry -> verify names `bypass`. First show the chain ALONE (no executed set) accepting it — absence is invisible to the chain — then the coverage cross-check catching it.
- **Scene 5 — TRUNCATION (the moat).** Drop the last 2 records. Show `verify()` WITHOUT the anchor returns `valid True` (THE DEFEAT — a naive verifier accepts the dropped tail). Then `verify(expected_head=anchor)` returns `truncation @ <count>`. Print the moat sentence.
- **Scene 6 — VETO + DEMOTE in action.** Show the veto at seq N precedes the action at N+1 (ordering provable); show every decision after the demote carries the lower tier, and a forged "still at high tier" later decision is caught as edit.

Closing block prints: "The test IS the control — run `./run_tests.sh`. Set `_CHECK_TRUNCATION=False` in verify.py and `test_polarity_truncation_strip_makes_it_pass` turns RED."

## 5b. Polarity-proof design (exact strip-points)

Three module-level booleans in `verify.py`, each defaulting `True`, each guarding exactly one check block:
- `_CHECK_EDIT` guards `_check_links_and_edit` (strip-point E).
- `_CHECK_REORDER` guards `_check_sequence` (strip-point R).
- `_CHECK_TRUNCATION` guards `_check_truncation` (strip-point T — centerpiece).

A reviewer flips ONE constant to `False` in source (or the polarity tests monkeypatch it) and watches EXACTLY ONE forgery test go RED while the others stay green (`test_polarity_each_strip_fells_exactly_one_class` proves the isolation). Restoring -> green. This is the documented, auditable mechanism that proves each check is load-bearing and that the suite asserts PRESENCE of the safe condition (the forgery is CAUGHT), not mere absence of an unsafe one.

## 6. Reg-anchor mapping

The ledger maps to **SEC Rule 17a-4(f), specifically 17 CFR 240.17a-4(f)(2)(i)(A)** — the audit-trail alternative to WORM. That clause requires an electronic recordkeeping system to maintain "a complete time-stamped audit trail that records all modifications to and deletions of a record," the date/time of every create/modify/delete, and (where applicable) the identity of the actor, such that the original can be re-created if modified or deleted (alternative (B) = non-rewriteable non-erasable WORM; retention 6 years per 240.17a-4(a); 2022 amendment = SEC Release 34-96034). This anchor is already present and `framing_confidence: confirmed` in the canonical SSOT as id `sec_17a_4_f` (verified 2026-06-19); this build cites it verbatim via the `REG_CITE` constant and does NOT re-derive or edit the SSOT.

The control-invariant mapping ("complete audit trail of all modifications and deletions"):
- **"all modifications" detectable** -> the **edit** check (recompute-link mismatch) plus **reorder** (seq bound into the hash). Any in-place change to a record is detectable and localized to an index.
- **"all deletions" detectable** -> the **delete** check (chain discontinuity) AND the **truncation** check (external head anchor) — together they cover deletion of an INTERIOR record and deletion of the TAIL, which a bare chain misses. This pairing is the precise fit for "all deletions of a record."
- **"complete" audit trail (no off-book gaps)** -> the **bypass** coverage invariant (gap-free monotonic seq + every governed action carries a recorded receipt) — the clause's word "complete" maps to absence-of-gaps, which the chain alone cannot prove.
- **"identity / authority of the actor" + ordered create/modify/delete** -> `authority_tier` bound into every decision entry, plus the veto and demote records carried IN the same chain — the audit trail records not just the change but WHO was allowed to make it and WHEN, ordered.

The centerpiece (truncation) is exactly the "deletions … enabling re-creation of the original" requirement applied to the tail: a system that silently accepts a dropped tail cannot re-create the original and fails 17a-4(f)(2)(i)(A).
